# 插件模块目录（新增分析方法往这里丢文件）

## 为什么有这个目录

用户会持续把新的分析方法加进来。为避免"每加一个方法就改执行器"（违反单一职责、
也容易改坏已验收的流水线），执行器 `bio_pipeline.py` 在启动时会扫描本目录下的
`*.py`（跳过 `_` 开头的文件），自动注册其中的模块。

## 插件契约（三件事）

```python
# 文件名：建议 m<编号>_<英文短名>.py，如 m17_sample_similarity.py
MODULES = [                      # 必须叫 MODULES，列表
    {
        "id": "M17",             # 唯一编号 M<两位数字>，不得与已有模块冲突
        "name": "样本相似性与离群检测",
        "folder": "样本相似性",   # 运行归档子目录名（第几执行顺序由 config 决定）
        "deps": ["M03"],         # 声明依赖，供装配校验提示顺序问题
        "fn": run,               # def run(ctx, out) -> str；返回一句话结果摘要
    }
]
```

- `fn(ctx, out)`：`ctx["config"]` 是本次配置（含 `params[M17]` 合并后的键值），
  `ctx` 中还可能有上游模块放入的对象（如 `ctx["expr"]`、`ctx["samples"]`）；
  `out` 是该模块自己的归档目录（编号 + folder 已建好）。
- **所有阈值/开关必须从 `ctx["config"]` 取**，禁止在代码里写死（工程手册"配置天条"）。
- 返回值是一句话摘要（进 `pipeline_log.txt`）；产物写进 `out`；不要 `print` 大段内容。
- 允许失败：识别不了/不满足前提时**如实报错或返回"待复核"**，不得假装成功。

## 加载失败会怎样

单个插件加载或语法出错，只打印 `⚠ 插件 xxx 加载失败（已跳过）`，不影响既有模块。

## 参考实现

- `m17_sample_similarity.py`：真实可用插件（样本相关矩阵 + 离群候选），
  契约测试见 `../test_module_contracts.py`。
- `_模板_plugin.py`：以 `_` 开头，**不会被加载**，复制改名后使用。
