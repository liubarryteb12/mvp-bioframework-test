## 2 本轮解决的核心问题

### 2.1 判据结构化(上一版 P0 → 已解决)

`crossval/schema/criteria.yaml` 现在提供:

```yaml
- id: T13b
  inputs: [y_true, p_pred_cv, n_boot]
  predicate: "ci_covers(calibration_slope_bootstrap(...), 1.0)"
  pass_when: true
  on_fail: {action: "F3 + 不得用于个体风险预测", blocking: true}
  decidable: auto
  requires_tools: [bootstrap, logistic_fit]
```

**这是本轮最有价值的改动。** 从散文到结构化,意味着 Agent 可以直接读 YAML 执行,
不需要从自然语言里"理解"判据——后者是幻觉的主要来源。

`decidable` 三态标注分布:**auto 12 / hybrid 3**(补齐后 auto 16 / hybrid 3),
且**没有缺标注的判据**。这一点上一版是完全空白。

### 2.2 版本冲突消解(上一版 P0 → 已解决)

上一版我警告:"文档内部存在多处版本冲突,LLM 会在冲突处随机选一个,或幻觉出一个折中版本。"

本轮的处理:
- `判据权威版本.md` —— **单一权威源**,显式声明冲突消解顺序
  (`本文件 > S20/S21 > S15-C > S19(已废弃) > A2C 早期`);
- `S19` 加了 **⛔ 废弃横幅**,明确"其中的判据条文一律不得执行";
- `S15-C` 的 T13(c) 加了**修订指向**,说明第 6 条已被 S20 §2.3 取代。

**这个处理是对的。** 特别是"废弃文档保留但不删除"——既防止误用,又保留证伪过程可追溯。

### 2.3 工具契约(上一版 P0 → 部分解决)

`detect_backend()` 现在返回**实际使用的**后端而非"可用的":

```
[工具契约] PDF 检测后端 = pypdf_recursive(跨平台主路径) +poppler可用
```

**这里有个细节值得肯定**:作者发现"报告 poppler 可用但脚本用 pypdf"是不诚实的,
改成了报告实际使用的,并说明"为跨平台一致统一用 pypdf"。这比单纯追求"用权威工具"更务实。

契约的 `on_unavailable: fail_with_reason` 也写对了——**禁止静默通过**。

## 3 仍未完成的三项 P0

### 3.1 上下文分层未做

审核包现在 ~100K 字符 + 两个脚本全文。分层策略在 `S21-C §7` 里**写了但没实现**:

- 没有 Layer 0/1/2/3 的实际切分文件;
- 没有按需加载机制。

**后果**:8K/32K 上下文模型加载全文会爆;长上下文下早期硬阻断会被遗忘。

**建议**:产出 `layers/` 目录,把审核包切成 4 个物理文件。

### 3.2 全局不变量未独立成文件

`S21-C §7.2` 说要单独抽 `INVARIANTS.md`,**但该文件不存在**。

不变量(硬阻断 9 条、R1–R6、措辞硬规则、禁止 LLM 生成数字、禁止软化判定)
目前散落在 YAML 的 `invariants` 字段里,**每次调用不会自动注入**。

**建议**:立即产出,并在每次 Agent 调用时强制注入。

### 3.3 无 run_id / input_hash / env_snapshot

`report.json` 有 `summary` 但没有:
- `run_id`(唯一标识,便于回溯)
- `input_hash`(数据集 + 脚本 + 版本的 sha256)
- `env_snapshot`(pip freeze)
- `parent_run_id`(判定链 DAG)

**后果**:出了问题无法回溯"是哪个输入、哪个环境、哪次运行"。

## 4 新发现的问题

### 4.1 `decidable: hybrid` 的判定指引缺失

YAML 里 T06、T16、Y6、B03A 标了 `hybrid`,意思是"脚本给证据 + 人下结论"。
但**没有给人类判定者的指引**(judge_rubric)。

**这是空规的风险点**:`hybrid` 若无 rubric,就退化成"随便判"。

**建议**:每条 `hybrid` 增加 `judge_rubric` 字段,列出人类判定者要看什么、怎么下结论。

### 4.2 数值容差未定义

上一版我指出"完全一致"这个说法没有给出容差。本轮仍未处理:
浮点运算在 numpy/scipy/sklearn 版本间有 1e-6 级差异,Agent 做精确比对会误报失败。

**建议**:`atol=1e-3`,并把"完全一致"改为"在容差内一致"。

### 4.3 错误恢复策略仍无状态图

`on_fail` 给了 action(如 F3),但**没有状态转换图**:
Agent 判"不通过"后,是回退?回退到哪?请求人工?记录继续?

`B02-S` 可行性 gate 是唯一有完整三态输出的,其余判据没有。

## 5 LLM 特有失败模式的覆盖情况

| 失败模式 | 覆盖 | 说明 |
|---|---|---|
| 幻觉数字 | **部分** | `invariants` 里写了"禁止 LLM 生成数字",但**无输出层守卫强制执行** |
| 指令遗忘 | 未做 | 需"每 N 步重注入不变量",无实现 |
| 判据软化 | **已覆盖** | V2/P4 的"判不了"合法出口 + "禁止软化判定"入不变量 |
| 工具调用幻觉 | **已覆盖** | `require_raw_stdout: true`,禁止文字转述 |
| 合成值泄漏 | **已覆盖** | `09_guard.py` 路径断言,3/3 拦截 |

**最缺的是输出层守卫**:写了规则但没有机器强制。规则写在 YAML 里,LLM 仍可能违反。

## 6 结论

**接近可生产化,差 3 项 P0。**

优先级:
1. **P0**:产出 `INVARIANTS.md` 并在每次调用注入
2. **P0**:加 `run_id` / `input_hash` / `env_snapshot`
3. **P0**:`hybrid` 判据补 `judge_rubric`(否则是空规)
4. **P1**:上下文分层物理切分
5. **P1**:数值容差 `atol=1e-3`
6. **P2**:输出层守卫(禁止 LLM 生成数字的机器强制)

> 一句话:**结构化的骨架已经立起来了,现在缺的是让它在长会话里不退化的运行时机制。**
