## 0 我的决定与理由

**决定:不代理 C。冻结推进,固化状态,等指挥席重建。**

三条理由:

**① 分权是这个框架唯一真正的产品。**
条款可以重写,判据可以再算,但"**执行方不自判、判定方不下令、指挥方不计算**"这个结构一旦破,写多少条款都没用。我若在 C 宕机时接管,就是把出题、判定、下令三权集于一身——这正是我一路警告的"让执行方自判自己是否触发硬阻断"的极端版本。**C 宕机不是违反纪律的理由,恰恰是最该守住纪律的时候。**

**② 当前恰好是损失最小的断点。**
G6 未注入 → B 未跑真实数据 → **没有任何结果数字进入流程**。所有现存产物都是框架层与合成验证层,**全部可再生**。若 C 在 B05 之后宕机,那才是真麻烦——现在不是。

**③ 继续产出文档反而是当前风险最高的选项。**
它会同时做两件坏事:制造"在推进"的错觉;增加一批**未经指挥席拍板**的条文,等 C 回来反而是负担。我上一轮已经论证过"规则无限增殖"本身是风险——在没有拍板者的情况下增殖,风险翻倍。

## 4 三种恢复路径

### 路径 A:重建指挥席(推荐)

1. 新开一个 Arena 会话作为 C'
2. 喂给 C' 三样东西:**框架 v1.7 + 本恢复包 + S15-C**
3. C' 零成本接续

> **成本最低,风险最低。**因为所有状态都固化在文档里,不依赖 C 的记忆。

### 路径 B:C 恢复

直接把本恢复包 + S15-C 给 C,从 §2 核对表确认知识状态后继续。

### 路径 C:无指挥席,最小可行推进

若短期内不打算重建指挥席,可在**不改写框架**的前提下推进:

1. **用户注入 G6**(唯一硬阻塞,不受影响)
2. **B 单独执行**:以 **v1.7 + S15-C 的条文**作为执行标准
   - 关键:S15-C 的 10 条**属"执行判据"而非"框架本体修订"**,B 可直接用作执行标准,**标注来源 = A 侧建议·未经拍板**
   - 这样即使条文未落盘,项目也能动,且不违反留痕纪律
3. **A 的判定职能**:我可继续做判定,但每份判定须标注 **"未经指挥席确认"**
4. **风险**:失去交叉比对环节(A 与 B 的结果无人仲裁),分歧无解

**路径 C 的代价**:框架降级为"双人协作",防错能力约降至 70%。

## 5 陷阱清单(看起来完成,其实没有)

> 这些是我实际踩过或实跑验证会踩的坑,交接时**必须口头交代,不能只靠文档**。

| # | 假象 | 真相 | 防法 |
|---|---|---|---|
| 1 | 目检"字体已嵌入 = 合规" | **Type 3 也是 emb=yes**,但期刊普遍不接受。**我自己犯过** | 查 `pdffonts` 的 **type 列** |
| 2 | "无位图对象 = 矢量" | `pdfinfo\|grep image` 对"PNG 塞 PDF 外壳"**返回 0** | 用 `pdfimages -list` |
| 3 | 校准"斜率≈1 = 合格" | **训练内拟合必然≈1**(实测 1.001),恒合格 | 必须用 **CV 预测概率** |
| 4 | "ΔAUC 正向 = 有增量" | ΔAUC=0.0397 < 0.05 → **F3,无增量** | 判据是 0.05 且 CI 下限>0 |
| 5 | "DCA 区间内净获益优" | 可能全区间只有 0.485,**区间内 0.840** | **全区间 0.01–0.99 强制报告** |
| 6 | "两队列合并后 OR 居中 = 一致" | 可能 **I²=96.3%**,根本不该合并 | 合并前报 **I² 与事件率** |
| 7 | "细胞级 p=6.5e-11 = 极显著" | 患者级 **p=0.407**,伪重复 | 推断单位必须 donor/患者 |
| 8 | "分支覆盖 ≥6/8 = 达标" | 可能**跳过了硬阻断**(分支 8) | 分支 8、4 **必覆盖** |
| 9 | "程序定义敏感性稳健" | 改权重只漂移 1.8%,**换成员集漂移 13.9% 且翻转** | 变体须为**成员集实质变更** |
| 10 | "只报主种子 OR=1.645" | 换种子 **1.484–1.802**,极差 20% | 极差>10% **必须显式报告** |
