## 1. 硬阻断 9 条（违反即停止，不得降级为"警告"）

1. 伪重复：推断单位必须是独立受试者（donor/患者），**不是细胞/样本**
2. 数据泄露：特征筛选必须在交叉验证折**内**进行
3. 终点不等价：不同量表的终点**禁止**合并主分析
4. 数据集独立性：外部验证集**不得**参与任何调参
5. 数据集不当批次校正：禁止把数据集当批次用 ComBat/regression 抹除
6. 事后改阈值：分析开始后修改预注册阈值 = R3 回退
7. 台账外数字：任何数字必须有台账出处
8. 未预注册的分析：事后补的分析不得作为确认性证据
9. 利益方向不一致的判定：执行方不得自判（需独立判定方）

## 2. R1–R6 回退

| 代码 | 含义 |
|---|---|
| R1 | 分析计划未预注册 → 回退到 B03 |
| R2 | 阈值未冻结 → 回退到阈值预注册 |
| R3 | 事后修改阈值/分析 → 结论降级为探索性 |
| R4 | 台账外数字 → 该数字作废 |
| R5 | 复现不一致 → 判"不确定"，保留不补齐 |
| R6 | 硬阻断触发 → 停止，回退到上一节点 |

## 3. 措辞硬规则

- 禁止"显著"用于未达预注册阈值的结果
- 禁止把"探索性"表述为"验证性"
- 禁止把"候选"省略为"标志物"
- 证据分级 L0–L4 为**内部标签**，不得对外表述
- 禁止用"原则上""视情况""基本"软化判定

## 4. 判定纪律

- 每项判据须给出**明确结论**：通过 / 条件通过 / 不通过 / 判不了
- **"判不了"是合法结论**，但必须附缺口登记
- 禁止为规避"判不了"而给出无依据的判定
- 有 P0 未完成 = "条件通过"或"不通过"，**不得**判"基本可用"

## 5. 第 11 条陷阱（元级）

> **一个从未 FAIL 过的守卫，和没有守卫，在证明力上等价。**

每个新增守卫必须通过 `guard_selftest.py` 变异测试：注入已知违规，验证抓得到。
抓不到 = 空规，不计入"通过"。

## 6. 数字纪律

- 数字唯一来源：`report.json` / `guard_results.json` / `criteria.yaml`
- **禁止 LLM 生成数字**，所有数字必须来自脚本输出
- 引用数字必须带符号名（如 `diff_km`），禁止裸数
