# Handoff 交接规范 v1.0

> 起因:复审追问"工作证据链在哪"。盘点后发现:**没有**。
> 现有产物只有零散的"发出方 A"字样,无接收方、无状态、无接收确认、无链连续性校验。
> 那不是证据链,是便条——无法回答"谁在什么时间、把什么、以什么状态、交给了谁、对方收到没有"。

---

## 1 Handoff 定义

**Handoff = 一次跨角色交付的最小可审计单元。** 每次交接必须产生一份 handoff 记录。

### 1.1 必填字段(12 项)

| # | 字段 | 说明 |
|---|---|---|
| 1 | `handoff_id` | 唯一标识,格式 `H{nn}_{from}2{to}_{slug}` |
| 2 | `from` | 交付方角色(A / B / C / USER) |
| 3 | `to` | 接收方角色 |
| 4 | `time` | 交付时间(ISO) |
| 5 | `artifacts` | 交付物清单(文件路径数组) |
| 6 | `state_in` | 交付时输入状态(依赖哪些前置 handoff) |
| 7 | `state_out` | 交付后输出状态(通过 / 条件通过 / 阻塞 / 不适用) |
| 8 | `blocking` | 阻塞项清单(无则 `[]`) |
| 9 | `actions_required` | 要求接收方做的事 |
| 10 | `checksums` | 交付物 sha256(前 16 位) |
| 11 | `ack` | 接收确认位(`null` = 未确认 / `{by, time, note}`) |
| 12 | `next` | 后继 handoff_id(链的下一环) |

### 1.2 三态接收确认

```
null                    → 未确认(在途)
{by, time, note:"确认"}  → 已接收
{by, time, note:"拒收"}  → 已拒收(须记录理由,链在此分叉)
```

> **关键**:`ack` 为 `null` 不算交接完成。这是现有产物缺失最严重的一项——
> 所有历史 handoff 均无确认位,**无法区分"对方收到了"与"我发出去了"**。

---

## 2 链连续性规则

1. 每个 handoff 必须能通过 `next` 指向后继,或显式标记为链尾(`next: null` + 终止理由)。
2. 非首节点的 `state_in` 必须包含其前驱 handoff_id。
3. **断链 = 审核不通过**:若某节点的 `state_in` 引用了不存在的 handoff_id,链断裂。
4. **未闭合 = 警告**:链尾若 `ack` 为 `null`,标记 `PENDING`。

---

## 3 机器校验

`scripts/handoff_guard.py` 检查:

| 检查 | 内容 |
|---|---|
| L-1 | 每个 handoff 12 字段齐全 |
| L-2 | `next` 指向的 id 存在(或为 null 且标终止理由) |
| L-3 | `state_in` 引用的前驱 id 存在 |
| L-4 | 无环(链是 DAG/线性) |
| L-5 | 每个非链尾节点的 `ack` 状态可枚举 |
| L-6 | `checksums` 与磁盘实际文件一致 |
| L-7 | 无孤儿节点(每个节点有入边或有 `is_root` 标记) |

---

## 4 与框架的关系

Handoff 是**流程层的证据链**,与框架的三层检查(形式/实质/目检)并行:

| | 管什么 |
|---|---|
| 框架三层检查 | **产物对不对**(内容) |
| Handoff 链 | **流程走没走完、走到哪了**(过程) |

> 二者不可互相替代。一份内容全对但交接未确认的产物,在流程上是**悬空的**。
